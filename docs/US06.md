# US06 - Correcao automatica e resultado

Requisito: corrigir apos envio e exibir gabarito e explicacao/resolucao detalhada.

## Arquitetura

- Authentication identifica o aluno. As callable functions exigem `request.auth`.
- `questions` e o banco privado existente, incluindo gabarito e resolucao. Apenas administradores (`admin: true` no token) podem consulta-lo e altera-lo diretamente.
- `startAttempt` entrega somente id, categoria, enunciado e alternativas. Copia as questoes completas para `attempts`, inacessivel ao cliente. Isso preserva a correcao mesmo se um administrador editar a questao depois.
- `submitAttempt` verifica propriedade, IDs e alternativas, calcula no servidor e grava `results` em transacao. Reenvios retornam o mesmo resultado, sem permitir alteracao de respostas apos o envio.
- `results` permite leitura apenas pelo proprietario e nenhuma escrita pelo cliente.
- O frontend retoma a ultima tentativa da conta neste navegador. O armazenamento local guarda apenas o identificador, que nunca concede acesso por si so.

O banco privado evita migracao destrutiva das questoes antigas. Nao se deve liberar sua leitura para alunos: regras do Firestore nao ocultam campos de documentos legiveis.

## Questoes e limites

O seed local agora inclui cinco questoes: Algoritmos, Banco de dados, Redes, Sistemas Operacionais
e Engenharia de Software. Execute `npm run seed:emulators` e abra uma nova tentativa para carregar
as cinco. Tentativas anteriores preservam a quantidade e o conteudo originais.

Para reproduzir a demonstracao a partir do Git em outro computador, siga o [README](../README.md).

O administrador precisa preencher `explanation` e marcar `published: true`. Questoes antigas sem esses campos permanecem indisponiveis para alunos. Os exemplos do painel sao criados como rascunhos e devem ter sua resolucao revisada antes de publicacao.

A integracao inicial oferece ate 10 questoes publicadas por tentativa (ordem do Firestore); a selecao por prova pertence ao fluxo da US04 e podera fornecer essa selecao no servidor. Ha limite de 30 novas tentativas por usuario/dia UTC e 5 instancias por funcao. Esses limites operacionais nao sao criterios do enunciado. Respostas omitidas contam como em branco e nao como acertos.

## Validacao local

Requer Node 22 (runtime de producao), Java 21+ e dependencias instaladas:

```powershell
npm ci
npm ci --prefix functions
npm test
npm run test:firebase
npm run build
npm run lint
```

Para usar a aplicacao com dados locais:

O caminho recomendado e `npm run demo`: um unico terminal inicia os servicos, verifica as
funcoes, executa o seed e abre o site. Node 22+, Java 21+ e as dependencias continuam necessarios.
Use Ctrl+C para encerrar. Os comandos abaixo sao a alternativa manual.

```powershell
$env:FUNCTIONS_DISCOVERY_TIMEOUT = '60'
npm run emulators
# Em outro terminal:
npm run seed:emulators
npm run dev:emulators
```

O modo emulator usa exclusivamente o projeto `demo-vem-pro-ppgi`. O modo normal continua apontando para o projeto real. Nao ha fallback automatico para producao. As contas dos emuladores sao independentes das contas reais.

O seed cria `aluno@example.test` e `admin@example.test` com senha local `TesteLocal123!`. O script fixa os enderecos dos emuladores e nunca usa o projeto real. Essas credenciais sao exclusivamente de desenvolvimento. Dados dos emuladores sao temporarios.

Nesta maquina, o prazo padrao de 10 segundos para descobrir as funcoes foi insuficiente; o comando acima permite 60 segundos. Os testes automatizados passaram: 4 testes de correcao e 5 testes de integracao com regras, autenticacao, propriedade, concorrencia, imutabilidade e limites. Build e lint tambem passaram. O runtime local disponivel e Node 24; o deploy esta configurado para Node 22.

Validacao no navegador concluida nos emuladores: login, envio com um acerto/um erro/uma resposta em branco (33%), exibicao das tres resolucoes e recuperacao do mesmo resultado depois de recarregar. Layout verificado em 390px e 1280px, sem rolagem horizontal. A sessao foi mantida apos recarregar com os emuladores ativos. Reiniciar os emuladores apaga seus dados temporarios e pode exigir novo login e seed.
